# Agent Operations v0.2.0

Agents can now use an installed GitHub issue operation with provider-specific verification, durable external waits and MCP access.

## Added

- Versioned operation packages and administrator-only installation with a connection check.
- GitHub.com issue creation with exact-action approval, case identity, independent verification and conservative recovery after lost responses.
- Optional waiting for the issue to be closed as completed, with bounded automatic read-only checks.
- Signed GitHub webhooks, persistent delivery deduplication and provider re-reads instead of trusting event order.
- A Packages dashboard, guided operation form, verified issue links and external-wait state.
- MCP stdio tools for installed operations and status, using the official MCP SDK.
- Python and TypeScript package helpers, a Deep Agents example and an opt-in live GitHub smoke script.

## Upgrade

Back up the database, stop all old workers/API processes, install the release and start the new version. Startup applies migration 3, adding package installations, webhook deliveries and recheck fields. Existing operation definitions remain valid. Do not run v0.1 workers against v0.2 external waits. Restore the backup to roll back; there is no down migration.

SDK consumers should recognize the new `WAITING_EXTERNAL` status. Existing wait methods continue polling through it; their timeout only stops the client from waiting, not the server operation.

## Validation

Validated against the real GitHub REST API in a private test repository: approved creation, MCP stdio submission/status, simulated response loss after GitHub accepted a write, repeat submission without a duplicate issue, and completed closure. GitHub list visibility can lag creation; recovery continues with read-only checks. Database and failure-path tests run against both PGlite and network PostgreSQL. Browser tests cover package installation and the waiting interface.

## Boundaries

The first package supports GitHub.com personal access tokens and issue creation/closure, not GitHub App tokens or automatic OAuth refresh. A missing or modified issue is never treated as proof that creation can safely repeat. Recovery scans are bounded. Creation verification and completed closure are separate results. Closing an issue does not prove that its underlying business problem was solved.

The GitHub smoke test requires a private validation repository and creates real test issues. Webhook signature, duplicate and ordering tests are local; successful outbound API validation does not imply live inbound webhook delivery has been tested.

See [package setup and execution boundaries](../packages.md), [MCP setup](../mcp.md) and [deployment](../deployment.md).

Core remains ELv2; SDKs and examples remain Apache-2.0. This release makes no production-scale or universal exactly-once claim.
